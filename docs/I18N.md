# Internationalization

This extension ships a single canonical English bundle and one checked JSON
bundle per locale. The registry, the runtime loader, the manifest folders and
the picker all derive from the same file: `i18n/locales.ts`.

## Architecture

```text
i18n/
  locales.ts              # locale registry + matching + direction + shipped status
  load-locale.ts          # lazy import.meta.glob loader; en is the static fallback
  index.ts                # i18next init, applyLanguage, <html lang/dir>
  locales/en.json         # canonical schema
  locales/<tag>.json      # complete bundle for each ready locale
  manifest-messages.json  # manifest copy for every Chrome locale
  i18next.d.ts            # typed static t() keys
  keys.ts                 # TranslationKey union for registries and runtime maps
```

`<html lang>` and `<html dir>` are written by `applyLanguage()`. Every Radix
surface is wrapped in `AppDirection`, which feeds the same direction into
Radix and Motion (`reducedMotion="user"`). `<html dir>` alone is not enough:
Radix submenus, collision handling and arrow-key navigation read their own
direction context.

`react: { useSuspense: false }` is deliberate: React renders outside Suspense,
so returning a key while a bundle loads would flash raw dotted strings.

## Locale codes

Two codes exist for the same language and must not be mixed:

- `tag` — BCP-47, used by i18next, `Intl.*`, `<html lang>` and storage.
- `chrome` — Chrome `_locales/<code>` directory name (underscores, no script
  subtags): `zh-TW` → `zh_TW`.

`status: 'ready' | 'draft'` separates *registered* locales from *shipped*
ones. A draft locale is still matched by `matchLocale`, but
`normalizeLanguage`/`detectLanguage` fall back to English until its bundle is
complete. The picker only lists `SHIPPED_LOCALES`.

## Adding a locale

1. Add one entry to `LOCALES` in `i18n/locales.ts` (or flip `status` to `ready`).
2. Add `i18n/locales/<tag>.json` with every key from `en.json`.
3. Run `npm run i18n:check`.
4. Run `npm run i18n:manifest` to regenerate `public/_locales`.
5. Add the manifest copy to `i18n/manifest-messages.json` if it is missing.
6. Add the locale to the manual screenshot matrix (RTL, long words, tall
   scripts).

Never hand-edit `public/_locales`: it is generated.

## Key conventions

- `common.*` — shared actions/nouns.
- `app.*` — product identity.
- `popup.*`
- `options.nav.*`, `options.appearance.*`, `options.about.*`
- `scripts.*` — scripts page.
- `editor.*` — editor, metadata and info panels.
- `settings.*` — settings page, including `settings.agent.*`.
- `logs.*`
- `install.*`
- `errors.*` — `ErrorCode` catalogue, rendered by `useErrorText`.
- `diagnostics.*` — metablock findings, rendered from `Diagnostic`.

Short labels use sentence case and no trailing period. Full sentences use a
period. Pending states use `…`, never `...`. Do not concatenate sentence
fragments at runtime: give each sentence its own key.

### Plural keys

Every count key is pluralised with i18next's v4 suffixes. English needs
`_one`/`_other`; Arabic adds `_zero`/`_two`/`_few`/`_many`; Russian adds
`_few`/`_many`; French/Spanish/Portuguese add `_many`. `npm run i18n:check`
uses `Intl.PluralRules` to require the categories the locale actually needs.

`{{count}}` is the only required placeholder in a plural key; do not translate
placeholder names or drop `{{count}}` from a form.

### Technical tokens

Keep these literal in every locale:

`Lumo`, `Lumo Userscripts`, `GM_*`, `@match`, `@include`, `@exclude`,
`@exclude-match`, `@grant`, `@connect`, `@require`, `@require-css`,
`@resource`, `@run-at`, `@inject-into`, `@noframes`, `@unwrap`,
`@top-level-await`, `@updateurl`, `@downloadurl`, `@storagename`,
`@antifeature`, `@run-in`, `USER_SCRIPT`, `MAIN`, `userScripts`, `MCP`,
`JSON`, `ZIP`, `URL`, `ID`, `HTTP`, `Chrome`, `Edge`, `GitHub`.

Do not translate user content: script names, namespaces, descriptions, tags,
URLs, agent names and script-authored log messages.

## Errors and diagnostics

The service worker, IndexedDB and the installer have no user language. They
return stable codes:

- `lib/errors.ts` — `ErrorCode` + `AppError` + `ERROR_KEYS`.
- `lib/diagnostics.ts` — `DiagnosticCode` + `DIAGNOSTIC_KEYS`.
- `lib/use-error-text.ts` — React hook that renders the localized headline and
  appends the raw technical detail when it differs.

`sendBg` reconstructs an `AppError` from `{ code, error, params }`, so a UI
catch block can call `errorText(e)` instead of rendering `e.message` directly.
The English detail stays available for logs and support.

## Text direction and typography

- Use logical utilities: `ms/me`, `ps/pe`, `start/end`, `text-start/end`,
  `rounded-s/e`, `border-s/e`. Physical `ml/mr/pl/pr/left/right` classes are
  rejected by `tests/i18n-direction.test.ts`.
- Mirror directional icons with `rtl:-scale-x-100`; do not mirror
  `ChevronDown`, clocks or media controls.
- Code, code editors, URLs, extension IDs, version numbers and match patterns
  stay LTR. User content uses `dir="auto"` / `<bdi>`.
- Arabic, Hebrew and Persian must not receive `letter-spacing` or
  `text-transform: uppercase`; both break the script's joining/typography.
- Use `Intl.NumberFormat`, `Intl.DateTimeFormat` and
  `Intl.RelativeTimeFormat` with the resolved BCP-47 tag. `formatBytes` takes
  the locale as its second argument.

## Tooling

| Command | Purpose |
| --- | --- |
| `npm run i18n:check` | key parity, empty values, placeholders, CLDR plural categories, zero-width characters, leftover markers, registry↔files |
| `npm run i18n:manifest` | regenerate `public/_locales` from `manifest-messages.json` |
| `npm run i18n:manifest -- --check` | fail when the generated tree is stale |
| `npm run i18n:scan` | fail on hardcoded visible JSX/attribute/HTML title strings |
| `npm run i18n:context` | generate the key → call-site report in `docs/i18n-context.md` |

CI runs `compile`, `i18n:check`, `i18n:scan`, `i18n:manifest --check`, `test`
and `build` before uploading the artifact. The publish workflow runs the same
gates before zipping.

## Translation review checklist

- [ ] Meaning matches the key's role (button, title, hint, aria, toast, empty state).
- [ ] Register is consistent across the whole locale.
- [ ] Glossary terms are consistent.
- [ ] No English left except the technical allowlist.
- [ ] Placeholders and plural categories are complete.
- [ ] Punctuation and typography match the target language.
- [ ] RTL punctuation, brackets and mixed LTR tokens are readable.
- [ ] Text fits the narrow options sidebar and 360px popup.
- [ ] Read every key in page order (list → editor → settings → install).
- [ ] Mark the bundle `ready` only after the checklist passes.
